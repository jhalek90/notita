# notita: notes for agents

## Project notes
- Build on this PC: system CMake is 3.25 (no VS 2026 generator) and there is no Ninja; use `build.bat` (vcvars64 + NMake) or call vcvars64.bat then `cmake --build build`. Bash `cmd //c "..."` quoting silently skips builds: run builds from PowerShell.
- `src/sim` must stay SDL-free; tests (`notita_tests [filter]`) and `notita_bench` link only `notita_sim` + `notita_script` (Luau), never SDL. For quick sim-only builds configure a second dir with `-DNOTITA_BUILD_APP=OFF`.
- Threading contract: a chunk update may read/write at most `kMaxReach` (32 px) outside its chunk; keep max fall/spread per tick <= 16 or the checkerboard passes race.
- Determinism contract: all randomness inside a tick comes from the per-chunk `Rng` passed to the update; never use global/thread-local RNGs or iterate unordered containers in the tick. `determinism_independent_of_thread_count` guards this.
- Cell is 16 bytes on purpose (`static_assert`); temperature is used by heat, life by flame/burn timers, aux is still free (bodies in phase 4). Adding fields means revisiting the size.
- Unknown keys in data/materials.txt land in `Material::extra`, so later phases can add properties without touching the parser. Material names/art are original; don't copy another game's.
- Rule tests use their own material table (tests/test_sim.cpp), so retuning data/materials.txt doesn't break them.
- Mass rule: every state change, burn-out and reaction must keep `Material::mass` (whole units; air and flames are 0). The registry/ReactionTable reject anything else at load. With the gas grid on, conserved mass is `World::totalMass * kGasMassOne + GasGrid::massFixed()` (grid mass is fixed-point ints, moved only as integer face fluxes); never delete gas cells, hand them over via `GasExchange`.
- Luau runs only at load time, in `notita_script` (src/script); `notita_sim` never links Luau and nothing scripted runs in the tick. data/reactions.luau must return a plain table.
- Heat runs inside the same checkerboard chunk job as motion and writes 1 px into the right/lower chunk; a chunk runs it when it moved or `heatNext` is set. Conduction pairs are capped (convex averages) so it can't blow up; keep that cap if you retune it.
- The Bash tool eats backslashes in inline heredocs (a `\n` inside arrives as a real newline): put edit scripts that contain escapes in a file first.
- Gas grid (src/sim/GasGrid.*): `GasGrid::step()` runs after `Simulator::tick()` (App::tickSim). `CpuGasSolver` (GasSolverCpu.cpp) and src/app/shaders/gas.hlsl are the same kernels in the same order: change both, then run `notita --gas-selftest` (needs a D3D12 GPU). CMake builds the .dxil with the Windows SDK's dxc into build/shaders/; without them the app silently uses the CPU solver.
- With the grid on, the sim's `ambientRate` is 0 (the grid carries air heat and counts its losses in `lostHeat/sourceHeat/latentHeat`), and every gas pixel is absorbed into the grid each step, so CA gas rules only run with the grid off.
- GasGrid touches pixels outside the tick: row-parallel jobs must stay 4 block rows apart (pushPixels) or run serially (condense, expandPockets, explode).
- Order per tick: `Simulator::tick` -> `ElectricSystem::step` -> `BodySystem::step` -> `ParticleSystem::step` -> `GasGrid::step` -> `Player::step` (App::tickSim, bench, tests). Conserved mass is `World::totalMass` (skips `kFlagBody` cells) + `ParticleSystem::totalMass` + `BodySystem::totalMass` + `Inventory::totalMass` (play mode); never delete a particle or a body pixel, hand it to the grid or the particle system.
- Player tools must act through the sim, not scripted moves: blasts go through `blastAt` (grid + bodies + player), jet gas through `GasGrid::jet` (the absorb path), rafts through `BodySystem::releaseClump`. The player is never stamped into the grid and can't dig `kFlagBody` cells (the body still counts them until its next step).
- `Cell::aux` is now used: on liquids it counts miscibility swaps (`mixSteps`); on solids 1 = `kAuxSettled` (put down by physics), 2 = `kAuxPinned` (scene geometry, never a body). Scene builders must pin their solids (`scenes::pinRect` / `PinnedScene`), or ledges fall as bodies. Solids made by a state change or reaction are `kAuxSettled`, and liquid or powder under a settled clump holds it, so magma crusts and pond ice stay put instead of spawning bodies.
- Bodies: Box2D v3.2 via cmake/Box2D.cmake (linked PRIVATE into notita_sim, no Box2D types in Bodies.h). Terrain shapes are rebuilt every tick, so Box2D sleeping is off and rest is judged by `BodyParams::restSpeed`; `kFlagBody` cells are stamps that are removed and rewritten every tick (the CA must never move them: only Solid kind gets the flag).
- Splashes only happen with a ParticleSystem attached (`Simulator::setParticles`); the splash reach is 3 px (inside `kMaxReach`), keep it there.
- Body buoyancy (BodySystem::applyLiquid) reads the pool surface in the columns just outside the body and only counts columns with liquid right under them (CA liquid never refills an air pocket under a body); floating bodies never freeze back into pixels, so a thin raft needs lots of liquid drag (`liquidDrag`) or it bounces.
- Streaming (src/sim/Streamer.*): the sim runs on a fixed awake window (16x8 chunks in the app) that `Streamer::follow` shifts; never add/remove world chunks behind its back. New per-chunk or per-grid-cell state that lives across ticks must go into `StoredChunk` / `GasGrid::ChunkCells` + ChunkCodec, or sleep/wake and saves silently lose it (`world_save_load_continues_identically` runs saved and loaded worlds in lockstep and catches it). Grid `open`/`src` count: particles, bodies and the player read them before the next grid step.
- Conserved mass with streaming = live + `storedMass()` (+ gas fixed) - `generatedMass()`; new terrain from WorldGen is the only source. Save format is versioned (`kSaveVersion`); bump it and keep reading old versions when the layout changes.
- Lighting: `src/light` (CpuLight, SDL-free, linked by the tests) and src/app/shaders/light.hlsl are the same kernels with the same integer stepping: change both, then run `notita --light-selftest`. Material keys `emissive`, `opacity`, `noise` (unknown-key path). F4 = lighting, Shift+F4 = dirty rects.
- WorldGen must stay a pure function of (seed, x, y) (any chunk order, seamless borders) and must pin its solids.
- Electricity (src/sim/Electric.*): material keys `electric`, `electric_role`, `voltage`, `toggles_into`, `splits_into`, `split_current`, `electric_heat` (unknown-key path). Potentials live per chunk in ElectricSystem (NaN = none), not in Cell; they travel via `StoredChunk::electric` and the save (v2). Effects (heat, lamps, sparks, electrolysis) only run on components whose solve has settled; keep that or half-solved fields melt wires. "Settled" needs both the local correction and the whole-piece Kirchhoff imbalance small: the local residual alone said "done" while a mesh was 50% off.
- Electric node loops use fixed `kBlock` node blocks with partial sums added in block order (overBlocks): never change a reduction to depend on the thread count. Lamp/spark/electrolysis effects stay serial with one per-tick RNG.
- Grain/liquid velocity (#477): powders and liquids now use `Cell::vx` (sideways roll / flow direction) and resting non-burning liquids use `Cell::life` as a surface-run counter; a grain must never take vy = 0 just because the cell below holds a *moving* grain (that was the chunk-border "steps"). `advance()` updates a still-falling cell in the top 15 rows of the chunk below (later pass) before the cell above it; keep that row limit or it breaks kMaxReach. Rule tests that need the phase 1 behaviour set `SimParams::smoothPowder` / `calmLiquid` = false; app screenshots to compare: `--lockstep` (+ `--old-look --old-motion`).
- Liquid look (#477): `GpuLiquid` reads the view texture as a read-only storage texture (Renderer adds COMPUTE_STORAGE_READ) and writes a screen-res texture that is blitted instead; release it before the GPU device in ~App like the other passes, or the app crashes on exit.
- The default scene is `showcase` (src/sim/Showcase.*): a `WorldOverlay` raster laid over WorldGen, so it streams and saves like terrain; keep it a pure function of (x, y) and edit it through the painter calls. Saves (v3) store the overlay name and loading switches the generator via `Streamer::setOverlayHook`. Showcase holds: Pinned = scene geometry, Loose = `kAuxSettled` (stays until its support is cut), Live = aux 0 (becomes a body at once, e.g. rafts).
- Run `notita_tests` from the repo root: `electric_game_data_is_valid` reads data/ relative to the working dir and fails from build/.
- The game is called "Fine Grain" on screen (window, title card, panels, exe version info, README); the name lives in src/app/Brand.h (+ src/app/notita.rc). The repo, CMake targets, `notita` namespace, notita.exe, notita_world.sav and the NOTITASV save magic stay "notita". "Whole Grain" is reserved for an every-system-on preset if one is ever added.
- Flames (#480): with the grid on (`SimParams::gridFlames` + `GasGridParams::gridFlames`, F11), burning pixels emit `GasEmission{mass 0, fuel > 0}` instead of flame pixels; fuel/soot/flame heat are CPU fields in GasGrid advected after the solve (not in the GPU solver, not mass). Fuel and soot are in `ChunkCells` (gas blob format 2; format 1 still reads). A Special material only becomes grid fuel if it has `flame_fuel`, so test tables without it keep the phase 2 flame pixels. The drawn temperature is `flameTemperature()` = max(cell, sub-cell flame heat): a 4x4 cell of air can't get flame-hot from pixel-sized energies.
- Textures (#481, src/sim/Texture.*): on a textured material `Cell::shade` is palette slot (high nibble) + brightness level (low nibble); untextured materials keep the old 256-step ramp. New pixels should take `Material::shadeAt(x, y[, along])` (a pure world-space function), not a random shade; state changes, burn residue, reaction products, condensed drops and electric toggles/splits do too (keep an existing RNG draw when swapping one out, so the sim stays identical). Flames, embers and sparks use `flickerShade(x, y, rng draw)` instead: a pure position would give a cell that keeps spawning flames the same colour every time. Cell blobs (format 2) store shade relative to `shadeAt`, so retuning texture keys re-looks untouched stored terrain (not a save break); format 1 (old saves) still reads. In materials.txt a `#` is a colour only right after `=` or after a comma.
- Scene builders in Scenes.cpp end with `scenes::textureCells` (shadeAt for every pixel, no RNG draws), so their `fillRect` shade draws must stay or the bench scenes change; a new builder must call it last too. Random shades on a textured material read as a weighted grain mix.
